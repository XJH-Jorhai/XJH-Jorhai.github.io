# 个人博客 · 单项目风格验证要求包

版本：1.0 · 2026-10-25

## 这份要求包要得到什么

**用一张真实项目图片，做出一个字体与图像主导、画面底色连续、鼠标响应丰富而克制的个人博客雏形；进入项目详情后，仍然适合阅读和维护。**

这是交给 Codex 执行的实现合同。它包含设计规则、技术选择、图片处理方法、任务范围和验收方式。它本身不包含已实现的网站，也没有预先替你生成项目图片。

## 你只需要提供两样东西

1. 本要求包：`blog-style-kit.zip`。
2. 一张你有权使用的、可正常打开的项目原始图片。无需提前抠图、修色、改名或制作深度图。

将两者交给具备文件读写和代码执行能力的 Codex，并粘贴 [START_PROMPT.txt](START_PROMPT.txt) 的内容。已有工作区时也可以先将要求包解压到工作区。若 Codex 无法读取某个附件，需要把该附件放进其可访问的工作区；无需改写本要求包。

图片是唯一必需的内容素材。项目名称、正式署名、说明文字可以以后补充；缺失时使用集中可编辑的中性占位，不编造研究结果。只有图片完全缺失、损坏，或执行环境阻止必要操作时，才需要报告具体阻塞。

## 文件分工与阅读顺序

| 文件 | 用途 |
| --- | --- |
| [START_PROMPT.txt](START_PROMPT.txt) | 直接粘贴给 Codex 的启动指令 |
| [AGENTS.md](AGENTS.md) | 项目级技术、复用、维护和执行规则 |
| [CODEX_TASK.md](CODEX_TASK.md) | 本轮工作范围、分阶段操作和交付清单 |
| [design.md](design.md) | 稳定的视觉与运动语言，以及可调初值 |
| [IMAGE_PIPELINE.md](IMAGE_PIPELINE.md) | 从唯一原图到网页素材的处理合同 |
| [ACCEPTANCE.md](ACCEPTANCE.md) | 以真实行为和画面为依据的验收 |
| [REFERENCES.md](REFERENCES.md) | 审美来源及官方技术资料 |

阅读全部文件后执行。技术约束以 `AGENTS.md` 为准；本轮范围以 `CODEX_TASK.md` 为准；视觉与动效行为以 `design.md` 为准；图片规则和验收各以专门文档为准。它们共同构成要求，不以一份文件为由忽略其他文件。当前用户指示及执行环境的权限规则始终适用。

## 最小成品的边界

- **两个真实页面**：主页 `/`；唯一项目详情 `/projects/project-01/`。
- **一张原图的一套派生素材**：处理后的完整画面、响应式版本、柔焦版本，以及有价值的局部裁切。
- **三项核心交互**：背景鼠标轨迹；标题局部响应；项目封面的跟随与模拟聚焦。
- **一套可继续使用的结构**：Markdown 内容、统一样式变量、独立动效模块、可重复的图片处理脚本。
- **一次有证据的自检**：静态版面、动态行为、移动端、键盘与减少动效模式均按清单检查。

本轮只完成一个视觉方向。配色和裁切由 Codex 看图后决定并记录，无需让你先选三套风格。暂不加入 CMS、账户、评论、搜索、Agent 论坛或完整作品档案。

## 最终应该收到的内容

Codex 应交付可运行的项目代码、锁文件、运行说明、处理后的图片、处理配方、验证报告及其截图／动态证据。根目录保留 `design.md` 和 `AGENTS.md`。正常桌面环境中的三项核心交互必须完成；移动端静态适配不能替代这项要求。

首次安装后，项目应能用文档中的确定命令启动、构建和预览；不依赖付费图片服务、登录或额外的三维素材。需要下载的开源依赖和可选模型应有出处，遵守当前环境的网络与权限限制。

## 以后怎么继续使用

新增项目时，修改内容文件和图片配方即可。正文与页面组件分离；颜色、字体和运动参数集中调整。以后选择新的实现工具，不应改变这里已经确定的艺术方向。

不要把本轮未知的项目名称、临时正文或配色初值提升为永久品牌规范。
