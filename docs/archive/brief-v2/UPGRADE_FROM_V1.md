# 从 v1 升级：本轮修改合同

版本：2.0 · 2026-10-25

## 1. 首先承认旧要求的边界

v1 明确允许以下默认路线：

- 封面由清晰图与预模糊图，通过 CSS 蒙版混合。
- 深度图、Three.js 和真正的三维渲染是可选增强。
- 背景可以通过 Canvas 2D 平滑轨迹和衰减完成。

这些要求能解释“会平移、会缩放、会聚焦，但不像改变观察视角”的结果。不要把升级说明写成未查看源码便认定旧实现有错误。

用户本轮明确要求更完整的 WebGL 空间交互与更好的轨迹形态，因此需要更新实现目标与验收。

## 2. 先检查实际项目

读取 package.json、项目规则、作品组件、动效代码、图片配方及原图路径。记录实际存在的实现，不靠依赖列表推断效果已启用。

只凭网页截图不能知道是否用了 WebGL，也不能评价轨迹的动态细节。本次截图能够支持的观察是：

- 灰褐色摄影背景与深绿页面有明显矩形边界。
- 照片前部外壳／盒盖占比较大，板卡主体处于较远区域。
- 图片容易被感知为一张放在文章中的照片，展示区域与大标题的联系较弱。

重新看原图后再决定裁切、层次与观察锚点。不要从截图推导真实尺寸。

## 3. 必须同步替换的旧约束

| v1 | v2 |
| --- | --- |
| CSS 清晰／柔焦合成为正常桌面默认 | Three.js + WebGL2 是正常桌面主路径 |
| 深度资产可有可无 | 深度资产必须生成、记录来源并实际驱动空间代理 |
| 图片承载层平移／倾斜 | 相机围绕稳定观察目标小幅变化；前后元素有一致相对视差 |
| 鼠标附近清晰、周边模糊 | 焦点来自场景深度；同一深度有一致的模糊关系 |
| 后处理可选 | 实际颜色／深度、景深、输出与必要抗锯齿链必需 |
| 平滑线条或点的衰减足以证明轨迹 | 背景必须有受速度影响的连续平流、形变、扩散与消退 |
| CSS 路线可通过主验收 | CSS／静态只作为触控、减少动效和失败回退 |
| C01–C08 验收 | 改用本包 W01–W10；增加可关闭模块的对照证据 |

旧清晰蒙版不能继续叠加在 WebGL 主路径上，以免两个焦点系统打架。保留它仅在确实有价值的回退分支，不为保留旧代码增加多余复杂度。

## 4. 优先级

1. 找到原图与已有代码，建立可回退的本地修改。
2. 调整主视觉构图，明确观察对象和稳定锚点。
3. 生成有效的相对深度与必要蒙版，构建空间代理。
4. 在无景深、无轨迹状态下做相机跟随，并通过平深度对照。
5. 完成基于当前深度的景深，核对颜色／几何／对焦的一致性。
6. 完成后处理输出与背景流场，调整艺术质量。
7. 完成适配、故障回退、性能检查与报告。

不要先加 bloom、色差、粒子或更大的 tilt，期待它们弥补没有空间几何的问题。

## 5. 可保留与可修改的范围

保留已完成且符合要求的内容、路由、Markdown、页脚、正文和无障碍行为。允许调整首屏图像尺度、背景衔接、标题位置和留白，使展示区域更集中。

维护新版 design.md 与 AGENTS.md；将旧版本归档或清楚标记为过期，避免 Codex 同时遵守互相矛盾的默认路线。不要覆盖仓库中与本任务无关的规则或用户修改。

最终报告同时列出“保留了什么”“替换了什么”和“尚未验证什么”，并给出本轮实际证据。
